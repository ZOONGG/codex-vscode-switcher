# Codex VS Code Switcher

Codex VS Code Switcher — независимое Windows-приложение для запуска одного изолированного управляемого экземпляра Visual Studio Code с выбранным профилем Codex.

Текущий стабильный релиз — **v1.0.0**. Скачайте отдельный `CodexVsCodeSwitcher.exe` или полный portable-пакет `CodexVsCodeSwitcher-win-x64-portable.zip` в разделе [GitHub Releases](https://github.com/ZOONGG/codex-vscode-switcher/releases/latest). Проверьте скачанный файл по `SHA256SUMS.txt` из того же релиза.

Программа не переключает ChatGPT Desktop, не заменяет общий файл авторизации и не управляет обычными окнами VS Code.

## Изоляция

Управляемый экземпляр всегда запускается так:

```text
Code.exe
  --user-data-dir "%LOCALAPPDATA%\CodexVsCodeSwitcher\VSCodeData"
  --new-window
  [необязательная папка или .code-workspace]
```

По умолчанию включено **«Использовать мои расширения VS Code»**, поэтому аргумент
`--extensions-dir` не передаётся и используется `%USERPROFILE%\.vscode\extensions`.
Обычный реестр приложений VS Code сохраняется, поэтому application-scoped расширения,
включая Codex, остаются включёнными. User data, настройки, cookies и `CODEX_HOME`
остаются изолированными. В расширенном изолированном режиме передаются
`--extensions-dir "%LOCALAPPDATA%\CodexVsCodeSwitcher\VSCodeExtensions"` и отдельный
`--shared-data-dir`.

`CODEX_HOME` добавляется только в `ProcessStartInfo.Environment` этого запуска и указывает прямо на выбранный каталог в `%USERPROFILE%\.codex-vscode-profiles`. Профиль и `auth.json` не копируются и не заменяются.

Изменяемые данные находятся только в:

```text
%LOCALAPPDATA%\CodexVsCodeSwitcher
%USERPROFILE%\.codex-vscode-profiles
```

Защищённые каталоги:

```text
%USERPROFILE%\.codex
%LOCALAPPDATA%\CodexProfileOverlay
```

## Добавление и замена аккаунтов

Нажмите **«Добавить профиль»** в панели, Настройках или окне управления профилями.
Введите любое локальное имя: Switcher создаст отдельный `CODEX_HOME` и откроет
официальный вход Codex в отдельном терминале. После успешного входа новый аккаунт
появится в списке и его можно сразу запустить. Профили обнаруживаются динамически;
в приложении нет встроенных имён пользователей, аккаунтов, файлов авторизации или
фиксированного ограничения на четыре аккаунта.

Удаление неактивного профиля перемещает его локальную папку в принадлежащий приложению
каталог `removed-profiles`, откуда её можно восстановить. Внешний аккаунт не изменяется.

## Проверка управляемого экземпляра

Окно считается управляемым только при одновременном выполнении условий:

- совпадают сохранённый root PID и время запуска процесса;
- точно совпадает путь к настроенному или найденному VS Code;
- в командной строке root-процесса есть точный `--user-data-dir`; общий режим запрещает оба аргумента переопределения storage, а изолированный режим требует точные `--extensions-dir` и `--shared-data-dir`;
- окно принадлежит root-процессу или проверенному потомку;
- HWND остаётся видимым окном верхнего уровня этого дерева процессов.

Одного имени `Code.exe` недостаточно. Заголовок окна не используется как идентификатор.

## Поведение панели

Панель больше не является глобальным окном поверх всех приложений. События foreground, сворачивания/восстановления, уничтожения, показа/скрытия и перемещения отслеживаются Win32 hooks; раз в две секунды выполняется защитная сверка.

По умолчанию панель:

- видна только вместе с foreground-окном управляемого VS Code;
- не исчезает при работе с собственными кнопками и меню;
- скрывается поверх ChatGPT, браузеров, Проводника, обычного VS Code, других редакторов, представления задач, чужих полноэкранных приложений и защищённых рабочих столов;
- скрывается при сворачивании или закрытии управляемого окна;
- возвращается после восстановления и фокусировки управляемого окна.

Сохранены режимы «Авто», «Компактный», «Развёрнутый», перетаскивание, масштаб, смещения, DPI, несколько мониторов и сброс положения.

Открытие Настроек создаёт явную интерактивную preview-сессию. Раскладка, ориентация, ширина, масштаб, смещения и положение меняются сразу, даже если Codex VS Code не запущен. После закрытия Настроек немедленно возвращается видимость только с проверенным окном Codex VS Code; preview не привязывается к окну Настроек и не запускает профиль.

## Переключение профиля

Переключения сериализованы и выполняются транзакционно:

1. проверяются профиль, exe, отдельные каталоги, расширение и workspace;
2. штатное закрытие отправляется только проверенным окнам управляемого VS Code;
3. программа ждёт VS Code и подтверждение несохранённых файлов;
4. новый экземпляр запускается с выбранным профилем и изолированными аргументами;
5. успех требует действительного процесса и видимого проверенного окна;
6. активный профиль сохраняется только после этой проверки;
7. при ошибке запуска один раз открывается предыдущий профиль.

Обычный процесс переключения не использует принудительное завершение.

Щелчок по профилю запускает этот сценарий напрямую. Выбранный профиль помечается как ожидающий и становится активным только после проверки нового окна. Успех, ошибка, тайм-аут и отмена всегда освобождают блокировку и снова включают кнопки профилей.

При первом запуске окно **«Какой проект открыть?»** предлагает выбрать папку проекта, файл проекта `.code-workspace` или открыть без проекта. Выбор атомарно сохраняется до продолжения исходной ожидающей активации профиля; после неудачного запуска проект остаётся доступен для повтора.

## Расширение Codex и workspace

Официальное расширение `openai.chatgpt` определяется в активной папке расширений. Общий режим никогда не устанавливает, не обновляет, не удаляет и не изменяет файлы или записи включения обычных расширений. Поскольку VS Code 1.131 помечает Codex как application-scoped, общий режим сохраняет обычный реестр приложений VS Code при отдельных user data и профильном `CODEX_HOME`. Поэтому официальный пакет OpenAI работает как production-расширение. Явная установка доступна только в изолированном режиме и использует отдельную папку.

В настройках доступны санитизированные проверки DNS/TCP/TLS/HTTPS/WebSocket/backend,
безопасное сравнение обычного и управляемого VS Code, allowlist-копирование настроек
прокси, необязательная передача пути через `CODEX_CA_CERTIFICATE`/`SSL_CERT_FILE`,
открытие журналов Codex, перезапуск extension host и сброс только диагностического кэша.

Отдельный `User\settings.json` обновляется атомарно с сохранением остальных корректных настроек. `chatgpt.openOnStartup` задаётся только там.

В состав Switcher входит небольшое companion-расширение, которое загружается только в отдельном Codex VS Code. Оно получает путь к каталогу bridge через локальное окружение процесса, атомарно передаёт только санитизированное состояние workspace/UI в `%LOCALAPPDATA%\CodexVsCodeSwitcher\bridge` и не открывает сетевой порт. В обычный VS Code расширение не устанавливается и при его запуске не подключается.

Файлы companion встроены в portable EXE и атомарно разворачиваются в `%LOCALAPPDATA%\CodexVsCodeSwitcher\companion-extension`. Поэтому один EXE, скопированный отдельно на Рабочий стол, сохраняет workspace bridge и автоматическое открытие Codex; соседняя папка из publish остаётся только резервным вариантом упаковки.

Папка или `.code-workspace`, открытые уже внутри Codex VS Code, автоматически становятся единым текущим проектом для всех Codex-профилей. Проект возвращается после смены аккаунта и перезапуска. В Настройках и tray доступны до десяти недавних проектов без дублей; исчезнувший проект остаётся в списке, пока пользователь явно не выберет другой, пустое окно или удаление.

После появления проверенного окна companion активирует официальное расширение и вызывает `chatgpt.openSidebar` с ограниченными повторами. Параметр **«Автоматически открывать Codex»** включён по умолчанию. `Ctrl+Alt+C` и компактная кнопка **Codex** в status bar снова открывают и фокусируют панель; существующее пользовательское сочетание показывается как конфликт и не перезаписывается.

Границей успешного запуска является проверенное управляемое окно. Отсутствующий/задержавшийся отчёт companion или ошибка команды панели показываются отдельным предупреждением и не превращают уже открытый Codex VS Code в ошибку запуска.

**«Импортировать мои настройки VS Code»** — необязательное действие с предварительным подтверждением. Оно показывает разрешённые settings, keybindings, snippets, файлы именованных профилей и число расширений. Базы хранилищ, сессии, учётные данные, cookies, machine ID, журналы и временные файлы не копируются. Выбранные расширения устанавливаются отдельно только в выделенный каталог.

**«Сбросить состояние Codex VS Code»** удаляет только устаревшие PID/время запуска/HWND после проверки, что точный управляемый экземпляр не работает. Профили, авторизация, workspace, настройки и расширения сохраняются. Отдельное действие создаёт ярлык **Codex VS Code**, не заменяя обычный ярлык Visual Studio Code.

## Сборка

```powershell
.\test.ps1
.\build-companion.ps1
.\build.ps1
.\verify-repository-safety.ps1
.\publish.ps1
.\publish.ps1 -ArtifactLabel real-e2e-test
.\smoke-test-workspace-restore.ps1
```

Результат:

```text
artifacts\publish\CodexVsCodeSwitcher.exe
artifacts\CodexVsCodeSwitcher-win-x64-portable.zip
artifacts\SHA256SUMS.txt
```

Перед проверкой реальных профилей используйте [чек-лист](docs/manual-test-checklist.md).

## Безопасность

Приложение работает локально, не содержит телеметрии и не записывает содержимое авторизации или полное окружение процессов в логи. Никогда не публикуйте реальные `auth.json`. Подробности — в [SECURITY.md](SECURITY.md).
